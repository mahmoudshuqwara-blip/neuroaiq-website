# Documentation workflow

Keep the GitHub repository Private.

## Updating documentation

1. Create an Issue describing one concrete gap and its completion criteria.
2. Create a branch for the related documentation change.
3. Update the relevant Markdown document and evidence references.
4. Commit with a specific message, such as `Document FTP response and matching event`.
5. Open a pull request explaining what changed, the evidence reviewed and remaining limitations.
6. Link the Issue. Close it only when its completion criteria are met.
7. Review the changes and merge.

Use actual work dates in the document and preserve normal commit dates. Do not recreate a misleading history of earlier work.

## Review checklist

- Claims distinguish recorded observations from reports and unknowns.
- Referenced attachments are either present or explicitly marked absent.
- Credentials and unrelated personal details are excluded.
- Links and evidence IDs are consistent.
- Repository visibility remains Private.
